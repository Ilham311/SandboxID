# Shell script review (`*.sh`)

The shell layer is **live on device** (no reflash), so it is where most fixes
land — but it runs as root against the Android framework, where the failure
modes are non-obvious. Enforce the conventions below; they are load-bearing.

## Dialect & lint gate

- **On-device scripts are `#!/system/bin/sh`** (POSIX / mksh / toybox):
  `action.sh`, `helpers.sh`, `rotate_ids.sh`, `autopif.sh`, `service.sh`,
  `post-fs-data.sh`, `summarize.sh`, `customize.sh`. **No bashisms** — no `[[ ]]`,
  arrays, `local`, `function` keyword, `${var^^}`, or `==` in `[ ]`. The one
  bash script is `build.sh` (`#!/usr/bin/env bash`, `set -euo pipefail`), which
  runs on CI, not the device.
- **CI blocks on lint** (`.github/workflows/build.yml:34-48`): `sh -n` / `bash -n`
  chosen by shebang, then `shellcheck -S warning`. A new/edited `.sh` must parse
  in its declared dialect and be shellcheck-clean at *warning* severity. Flag
  likely shellcheck violations (unquoted expansions, `SC2086`, useless `cat`,
  `read` without `-r`) as findings — they will fail CI.

## Framework CLIs — the #1 shell gotcha

Every `settings` / `pm` / `am` / `cmd` invocation **must** go through
`_fw_run` (`helpers.sh:96-104`) or native `run_framework` — i.e. run with
`</dev/null >/dev/null 2>&1` and retry. Reason (documented at
`helpers.sh:90-95`): `cmd(1)` forwards the caller's std FDs to `system_server`
over binder; when called from `action.sh` those FDs are a pty/pipe or a
`/data/adb` file the SELinux domain forbids, so the transaction fails with
`FAILED_TRANSACTION`. Pointing all three std FDs at `/dev/null` is mandatory.

- **`--user 0` goes AFTER the verb**: `settings put --user 0 …`,
  `am force-stop --user 0 …`, `pm clear --user 0 …`, `am kill --user 0 …`. A
  `--user` placed before the verb, or omitted where the target is user-scoped, is
  a finding.
- A raw framework call added *without* the `/dev/null` redirect (or bypassing
  `_fw_run`) is **Important** (it will intermittently fail on the action path).

## Control-flow & state

- `set -u` is used where safe (`rotate_ids.sh:3`) but **`set -e` is deliberately
  avoided** in scripts that tally failures (`rotate_ids.sh` counts `FAILURES` and
  reports `N step(s) reported failure`). Don't add `set -e` where it would abort
  a failure-tallying loop early.
- **`$MODDIR` convention**: entry scripts derive `MODDIR="${0%/*}"`
  (`action.sh`, `service.sh`, `post-fs-data.sh`); library/child scripts use
  `${MODDIR:-/data/adb/modules/sandboxid}` and are invoked as
  `MODDIR="$MODDIR" sh "$CHILD"`. The installer uses Magisk's `$MODPATH`.
- **Atomic config writes** via `helpers.sh identity_persist` (awk + rename).
  Don't replace with a non-atomic in-place edit.
- **Scoped SELinux** via `se_permissive`/`se_restore` (ref-counted, trap-restored)
  — see `10-security.md`. Don't leave permissive on an early `return`/`exit` path
  that skips `se_restore`.

## Kill-switches & cross-file string contracts

- **`no_uptime` is the only kill-switch file** (there is **no** `enable_uptime`).
  Checked via `[ -f "$MODDIR/no_uptime" ]` (`autopif.sh:260,317`) and in the
  companion. When active, the zeroed human uptime string must stay
  **byte-identical** across producers: `autopif.sh` emits `0d 0h 0m` and
  `companion.cpp` rewrites to `0d 0h 0m`. A change to one side only re-opens the
  bug that alignment fixed — flag it.
- **Ships-idle guard**: `post-fs-data.sh` and `service.sh` both gate on a
  `grep -qE '^[[:space:]]*[^[:space:]#]' target.txt` (a real, non-comment line).
  Removing/weakening this makes the module act with an empty target list —
  breaks the "idle by default" guarantee (Important/Critical).

## Data files — two schemas, don't cross-wire

- **`personas.tsv`** (read by the **native** CLI): tab-separated, **10 required**
  columns `model, device, product, board, platform, sdk, release, id,
  incremental, security_patch` (+6 optional). Native fallback pool for `freshen`.
- **`devices.tsv`** (read by **`autopif.sh device`** via `cut -f`): **15 columns
  in a different order**, `brand`-first, `sdk` **before** `release`, with a
  trailing `release_date`. The multibrand "Action" path.
- These are **distinct schemas with distinct readers** — reordering a column, or
  pointing one reader at the other file, silently mis-parses every row. `#` lines
  are comments in both. `target.txt` ships empty (0 bytes); one package per line.

## Versioning (CI-owned)

- `version` in `module.prop` must be `vX.Y.Z` (CI validates `^v[0-9]+\.[0-9]+\.[0-9]+$`).
  The `version=` line is parsed by **five** consumers (`app.js`, `rotate_ids.sh`,
  `service.sh`, `customize.sh`, `build.sh`) — keep the bare `version=vX.Y.Z` shape.
- **`versionCode` and `update.json` are regenerated by CI** on release — hand
  edits get overwritten. A PR that manually bumps `versionCode` or edits
  `update.json` should be flagged (let CI own them); human-authored version work
  is the `version=` line + a `CHANGELOG.md` `## <version>` block (the release
  notes `awk` depends on that heading shape).
