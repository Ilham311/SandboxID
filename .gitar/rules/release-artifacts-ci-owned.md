# Release artifacts are CI-owned

The build workflow regenerates `update.json` from scratch (`build.yml:167-183`)
and extracts release notes from the `## <version>` block in `CHANGELOG.md`. It
reads `versionCode` from `module.prop` as the base (`build.yml:65`) and only
raises it when it has to bump the version to skip an already-existing tag
(`build.yml:94-113`); on a normal new-version release it carries `versionCode`
through unchanged. So a hand-edited `update.json` is always overwritten, but a
hand-edited `versionCode` is kept — CI does not regenerate it.

When this rule matches, steer the author to the human-owned surface:

- Bump `version=vX.Y.Z` in `module.prop` (must match `^v[0-9]+\.[0-9]+\.[0-9]+$`).
- Bump `versionCode` in the same edit as `version=` — CI will **not** raise it
  for you on an explicit version bump (it only auto-raises on the tag-collision
  path, `build.yml:94-113`).
- Add a `## <version>` section to `CHANGELOG.md` — the heading must be literally
  `## vX.Y.Z` (optionally followed by a space and a parenthesised `YYYY-MM-DD`
  date), matching the release-notes `awk` (`build.yml:196-200`) and existing
  entries like `CHANGELOG.md:42` (`## v2.0.0 (2026-08-21)`). Do **not** use a
  bracketed Keep-a-Changelog heading such as `## [2.0.16]` — the matcher requires
  the `v`-prefixed form.
- Leave `update.json` for CI (regenerated every run).
